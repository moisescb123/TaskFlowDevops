## Original

Como Desarrollador quiero cambiar el estado de una tarea entre To Do, In progress y Done para reflejar el avance real del trabajo.

## Enhanced

**Story:** As a Developer, I want to move a task between To Do, In progress, and Done so that the board reflects real progress.

**Priority:** High | **Related:** RF05, RF08, RN04, US04

### Behavior

1. Developer moves a task (drag/drop or actions) between columns.
2. Allowed forward path: `todo` → `in_progress` → `done`.
3. Direct `todo` → `done` is rejected with a clear message (RN04); backend enforces even if UI is bypassed.
4. Backward moves (`done` → `in_progress`, `in_progress` → `todo`) are allowed.
5. Card appears in the target column without full reload when practical.
6. Viewer cannot change status (`403`).

### Fields and validations

| Field | Rules |
|-------|--------|
| `status` | Required; `todo` \| `in_progress` \| `done`; must obey RN04 transitions |

### Acceptance criteria

- **AC1:** Given task in To Do, when moved to In progress, then it appears in In progress.
- **AC2:** Given task in In progress, when moved to Done, then it appears in Done.
- **AC3:** Given task in To Do, when Developer tries Done directly, then `400` and status unchanged (RN04).
- **AC4:** Given Viewer, when they PATCH status, then `403`.
- **AC5:** Given unknown taskId, when status change is called, then `404`.

### Endpoints

- `PATCH /api/tasks/{taskId}/status` — `{ status }` → `200` / `400` / `403` / `404` / `401`
