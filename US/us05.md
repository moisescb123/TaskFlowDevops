## Original

Como Desarrollador quiero crear una nueva tarea en el tablero para registrar una actividad pendiente del proyecto.

## Enhanced

**Story:** As a Developer, I want to create a new task on the board so that I can register pending project work.

**Priority:** High | **Related:** RF01, RN01, RN02, US08/US10/US11, RNF03, RNF05

### Behavior

1. Developer opens create-task form from the board.
2. Submits **title**, **priority**, **due_date**, optional **assignee_id**.
3. Backend validates RN02 (title, due date, priority required); optional assignee must be a registered user and at most one (RN01).
4. Task is stored with status `todo` and appears in the **To Do** column without a full page reload when practical.
5. Viewer cannot create tasks (`403`).

### Fields and validations

| Field | Rules |
|-------|--------|
| `title` | Required; sanitized |
| `priority` | Required; `high` \| `medium` \| `low` |
| `due_date` | Required; valid date |
| `assignee_id` | Optional; existing User; single primary (RN01) |

- Missing/invalid → `400` with clear messages (RNF03).

### Acceptance criteria

- **AC1:** Given valid data, when Developer creates a task, then API returns `201` and the card appears in To Do.
- **AC2:** Given missing title, priority, or due date, when submitted, then `400` and no task is created (RN02).
- **AC3:** Given Viewer (or anonymous), when they POST create, then `403` / `401`.
- **AC4:** Given create succeeds, when board refreshes/updates, then assignee, due date, and priority show on the card.
- **AC5:** Given app restart, when board loads, then the new task persists (RNF02).

### Endpoints

- `POST /api/tasks` — `TaskCreate` → `201` / `400` / `403` / `401`
