## Original

Como Visor quiero consultar el tablero de tareas organizado por estado para conocer el avance del proyecto sin modificar la información.

## Enhanced

**Story:** As a Viewer, I want to consult the task board organized by status so that I can see project progress without changing any data.

**Priority:** High | **Related:** RF08, RNF02, RNF04, US05–US11 (data on the board), Viewer role

### Behavior

1. Authenticated Viewer opens the board.
2. System loads tasks and shows three columns: **To Do**, **In progress**, **Done**.
3. Cards show title, assignee, due date, and priority (labels/colors).
4. Mutating controls (create/edit/delete/move) are hidden or disabled for Viewer.
5. Developers also see the board (with mutate controls); this story’s acceptance focuses on Viewer read-only consult.
6. After app restart, the same tasks/states reappear (RNF02).

### Fields / validations

- No write fields for Viewer.
- Board read requires authentication (`401` if anonymous).

### Acceptance criteria

- **AC1:** Given a Viewer, when they open the board, then tasks appear in the three status columns.
- **AC2:** Given a Viewer, when they view the board, then no create/edit/delete/status-change actions are available.
- **AC3:** Given a Viewer calls mutating task APIs, when the request is processed, then the API returns `403`.
- **AC4:** Given tasks exist, when the app restarts and Viewer reopens the board, then data matches prior state (RNF02).
- **AC5:** Given Chrome/Firefox/Edge (latest two stables), when Viewer opens the board, then it works without plugins (RNF04).

### Endpoints

- `GET /api/tasks` → `200` Task[] / `401`

### Files / modules

- `templates/board.html`, `static/js/board.js`, `static/css/board.css`
- `app/routes/tasks.py` — list tasks; authz for Viewer read / deny writes
- `tests/test_board_viewer.py`

### Definition of done

- [ ] Board columns render by status
- [ ] Viewer read-only UX + `403` on writes
- [ ] Persistence across restart verified
- [ ] Pytest for list + Viewer forbid mutate

### NFRs / role impact

- RNF02 persistence, RNF04 compatibility, RNF03 clear empty/error states
- **Viewer:** consult only | **Developer/Admin:** may also view board (mutate covered in other US)

### Out of scope

- Creating/editing/moving tasks (US05–US11)
