## Original

Como Desarrollador quiero que la aplicación se despliegue automáticamente tras superar las verificaciones para publicar nuevas versiones de forma controlada.

## Enhanced

**Story:** As a Developer, I want the application to deploy automatically after verifications pass so that new versions are published in a controlled way.

**Priority:** Medium | **Related:** CD objective, US12–US14, RN03, Flask-compatible host

### Behavior

1. After CI (Pytest) succeeds on the agreed branch (typically `main` after merge), a CD job/workflow runs.
2. CD builds/packages or deploys the Flask app to the chosen Flask-compatible platform (e.g. Render, Railway, Fly.io, or similar — team picks one).
3. Deployment does **not** proceed if CI failed (RN03 / US14).
4. Successful deploy yields a reachable URL for demo/review.
5. Deploy logs are visible in GitHub Actions (or the host’s dashboard).

### Fields and validations

- N/A. Secrets (API tokens, `SECRET_KEY`, DB URL if any) stored in GitHub Actions secrets / host env — never committed.

### Acceptance criteria

- **AC1:** Given CI passes on `main`, when the CD workflow runs, then the app is deployed to the target environment.
- **AC2:** Given CI fails, when pipelines finish, then no production/demo deploy from that failing run occurs (RN03).
- **AC3:** Given a successful deploy, when the team opens the deploy URL, then the application responds (at least login or board reachable as implemented).
- **AC4:** Given deploy credentials, when inspected in the repo, then secrets are not in source control.

### Endpoints

- N/A for control plane. Deployed app serves the TaskFlow HTTP API/UI (`docs/api-spec.yml`).

### Files / modules

- `.github/workflows/cd.yml` or deploy job in existing workflow (deploy on `main` after tests)
- Host config / `Procfile` or start command as required by platform
- Env var documentation in `docs/development_guide.md`
- Optional health check route for smoke verification post-deploy

### Definition of done

- [ ] CD path defined and automated after green CI
- [ ] Secrets via platform/GitHub secrets
- [ ] Demo URL available for course presentation
- [ ] Failure of tests blocks deploy
- [ ] Documented for the team

### NFRs / role impact

- Controlled delivery; Developers merge to trigger; no end-user app role change
- Academic scope: single demo environment, not multi-stage enterprise CD

### Out of scope

- Blue/green, canary, multi-region
- Infra as full Kubernetes platform
