## Original

Como Desarrollador quiero editar una tarea existente para mantener actualizada su información cuando cambien las condiciones del trabajo.

## Enhanced

**Story:** As a Developer, I want to edit an existing task so that its information stays current when work conditions change.

**Priority:** High | **Related:** RF02, RN01, RN02, US08/US10/US11, RNF03, RNF05

### Behavior

1. Developer selects edit on a task card.
2. Form opens prefilled with current title, priority, due date, assignee.
3. On save, backend validates RN02 (and RN01 if assignee changes) and updates the task.
4. Board card updates without full reload when practical; changes persist after restart.
5. Viewer cannot edit (`403`). Status changes use US09 endpoint (optional: status not edited here).

### Fields and validations

| Field | Rules |
|-------|--------|
| `title` | Required if sent; non-empty |
| `priority` | `high` \| `medium` \| `low` |
| `due_date` | Valid date |
| `assignee_id` | Existing user or null; single assignee (RN01) |

- Clearing required fields → `400` (RN02); previous data unchanged.

### Acceptance criteria

- **AC1:** Given an existing task, when Developer saves valid edits, then `200` and the card reflects changes.
- **AC2:** Given empty title/priority/due date, when save is attempted, then `400` and data is unchanged (RN02).
- **AC3:** Given Viewer, when they PUT update, then `403`.
- **AC4:** Given unknown `taskId`, when update is called, then `404`.
- **AC5:** Given successful edit, when app restarts, then updates persist (RNF02).

### Endpoints

- `PUT /api/tasks/{taskId}` — `TaskUpdate` → `200` / `400` / `403` / `404` / `401`
- `GET /api/tasks/{taskId}` — optional prefills
