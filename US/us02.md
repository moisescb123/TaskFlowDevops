## Original

Como usuario autenticado quiero cerrar sesión para proteger el acceso a mi cuenta y al sistema.

## Enhanced

**Story:** As an authenticated user, I want to log out so that my session ends and no one else can use my account or access TaskFlow DevOps with my role.

**Priority:** High (security baseline after US01)

**Related:** US01 (login), RNF05 (security), all roles (Admin, Developer, Viewer)

### Behavior

1. Authenticated user (any role) selects **Log out** from the app chrome (board, admin, or shared header).
2. Client calls logout; backend invalidates the server session and clears the session cookie.
3. User is redirected to the login page.
4. Subsequent requests to protected endpoints or pages require a new login (`401` / redirect to login).
5. If the user is already unauthenticated and calls logout, the API responds `401` (or idempotent `204` if the team prefers safe no-op — default for this project: `401` per `docs/api-spec.yml`).

### Fields and validations

- No request body required for logout.
- Session cookie must be cleared on the client (`Max-Age=0` / expired) and invalidated server-side.

### Acceptance criteria

- **AC1:** Given an authenticated user, when they log out, then the session is destroyed and they are sent to the login page.
- **AC2:** Given a user just logged out, when they request `GET /api/auth/me` or a protected board/admin route, then the API returns `401` (or the UI redirects to login).
- **AC3:** Given an authenticated Admin, Developer, or Viewer, when they log out, then the same logout behavior applies regardless of role.
- **AC4:** Given a successful logout, when the browser still holds old client state, then mutating or reading protected data fails until a new login (US01).
- **AC5:** Given an unauthenticated caller, when they `POST /api/auth/logout`, then the API returns `401`.

### Endpoints (from `docs/api-spec.yml`)

- `POST /api/auth/logout` → `204` Logged out / `401` Not authenticated

### Files / modules to touch (expected layout)

- `app/auth/` — session invalidate / logout helper
- `app/routes/auth.py` — `POST /api/auth/logout`
- Shared layout/header — logout control visible when authenticated
- `static/js/auth.js` (or equivalent) — call logout, clear client state, redirect to login
- `tests/test_auth_logout.py` — Pytest for AC1–AC5

### Definition of done

- [ ] Logout control available for all authenticated roles
- [ ] Server session invalidated and cookie cleared
- [ ] Redirect to login after logout
- [ ] Pytest covers success and unauthenticated logout
- [ ] `docs/api-spec.yml` remains consistent with implemented behavior

### Non-functional requirements

- **Security (RNF05):** Invalidate session server-side; do not leave a reusable session id; secure cookie attributes unchanged from login setup
- **Usability (RNF03):** Logout is obvious in the UI; after logout the login screen is shown without cryptic errors
- **CI:** Logout tests included in the Pytest suite run by GitHub Actions

### Role impact

| Role | Effect |
|------|--------|
| Admin | Loses access to user/role configuration until login |
| Developer | Loses task CRUD access until login |
| Viewer | Loses board access until login |

### Out of scope (this story)

- Login (US01)
- “Log out all devices” / multi-session management
- Idle session timeout policy (can be a later story)
