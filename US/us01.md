## Original

Como usuario del sistema quiero iniciar sesión con mis credenciales para acceder a TaskFlow DevOps según mi rol.

## Enhanced

**Story:** As a system user, I want to sign in with my email and password so that I can access TaskFlow DevOps with the capabilities of my assigned role (Admin, Developer, or Viewer).

**Priority:** High (blocks all protected board and admin flows)

**Related:** US02 (logout), US03 (Admin creates users/roles), RNF03 (clear error messages), RNF05 (sanitize/validate input)

### Behavior

1. Unauthenticated user opens the login page.
2. User submits **email** and **password**.
3. Backend validates input, looks up the user, verifies the password hash, and creates a server session.
4. On success, the client receives the authenticated user (`id`, `email`, `full_name`, `role`) and redirects by role:
   - **Admin** → user management / configuration
   - **Developer** → task board (CRUD enabled)
   - **Viewer** → task board (read-only)
5. On failure, the UI shows a clear error and does not create a session.
6. Authenticated users who hit login again are redirected to their default landing page (or stay signed in).

### Fields and validations

| Field | Rules |
|-------|--------|
| `email` | Required; valid email format; sanitized |
| `password` | Required; non-empty; never logged or returned in responses |

- Invalid/missing fields → `400` with field-level message (RNF03).
- Unknown user or wrong password → `401` with a generic message (do not reveal which field failed).
- Passwords stored only as hashes (`password_hash` on `User`); never plain text.

### Acceptance criteria

- **AC1:** Given a registered user with valid credentials, when they submit login, then a session is created and the response includes their role.
- **AC2:** Given invalid credentials, when they submit login, then no session is created and a clear error is shown.
- **AC3:** Given missing email or password, when they submit login, then the request is rejected with a validation message.
- **AC4:** Given a successful login as Admin / Developer / Viewer, when the session is established, then subsequent authorized routes respect that role.
- **AC5:** Given an unauthenticated request to a protected resource, when access is attempted, then the API returns `401`.

### Endpoints (from `docs/api-spec.yml`)

- `POST /api/auth/login` — body `{ email, password }` → `200` `User` / `401` / `400`
- `GET /api/auth/me` — current user from session → `200` / `401` (supports post-login session check)

### Files / modules to touch (expected layout)

- `app/auth/` or equivalent — login service, password verify, session helpers
- `app/routes/auth.py` — `POST /api/auth/login`, `GET /api/auth/me`
- `app/models/user.py` + SQLite access — load user by email
- `templates/login.html` + `static/js/login.js` — login form and error display
- `tests/test_auth_login.py` — Pytest coverage for success, `401`, validation, role in response

### Definition of done

- [ ] Login form and API implemented against the data model (`User.role`: `admin` | `developer` | `viewer`)
- [ ] Password hashing verified; no plain-text secrets in code or logs
- [ ] Pytest cases for AC1–AC5 (TDD)
- [ ] `docs/api-spec.yml` remains consistent with implemented behavior
- [ ] Unauthenticated users cannot open the board or admin UI

### Non-functional requirements

- **Usability (RNF03):** Clear messages for validation vs auth failure
- **Security (RNF05):** Sanitize inputs; secure session cookie (`HttpOnly`, `SameSite`); `SECRET_KEY` from env
- **Persistence (RNF02):** Users come from SQLite; sessions survive within cookie lifetime across app requests (user records persist across restart)
- **CI:** Auth tests included in the Pytest suite run by GitHub Actions

### Role impact

| Role after login | Landing / access |
|------------------|------------------|
| Admin | Can reach user/role configuration (US03) |
| Developer | Full task board capabilities |
| Viewer | Board consult only |

### Out of scope (this story)

- User registration / role assignment (US03)
- Logout (US02)
- Password reset / OAuth / MFA
