## Original

Como Desarrollador quiero establecer la prioridad de una tarea (Alta, Media o Baja) para identificar qué actividades deben atenderse primero.

## Enhanced

**Story:** As a Developer, I want to set a task priority (High, Medium, or Low) so that the team can see what to handle first.

**Priority:** Medium | **Related:** RF06, RN02, US05/US06

### Behavior

1. On create/edit, Developer selects priority from **High / Medium / Low** only.
2. Backend stores `high` | `medium` | `low`; required on create (RN02).
3. Card shows priority via label or color.
4. Viewer cannot change priority (`403`).

### Fields and validations

| Field | Rules |
|-------|--------|
| `priority` | Required on create; enum `high`, `medium`, `low` only |

- Invalid/missing → `400` (RNF03).

### Acceptance criteria

- **AC1:** Given create/edit, when Developer opens priority control, then only High/Medium/Low are offered.
- **AC2:** Given a priority is set, when the card renders, then priority is visually clear.
- **AC3:** Given invalid or missing priority on create, when submitted, then `400` (RN02).
- **AC4:** Given Viewer, when they try to change priority, then `403`.

### Endpoints

- `POST /api/tasks`, `PUT /api/tasks/{taskId}` with `priority`

### Files / modules

- Priority select + card badge styles, validation in task service, `tests/test_task_priority.py`
