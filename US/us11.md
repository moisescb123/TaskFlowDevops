## Original

Como Desarrollador quiero definir la fecha límite de entrega de una tarea para planificar y cumplir los plazos del proyecto.

## Enhanced

**Story:** As a Developer, I want to set a due date on each task so that the team can plan and meet project deadlines.

**Priority:** Medium | **Related:** RF07, RN02, US05/US06, RNF03

### Behavior

1. On create/edit, Developer enters a due date.
2. Backend requires a valid date on create (RN02) and rejects invalid formats with a clear message.
3. Card displays the due date.
4. Viewer cannot change due date (`403`).

### Fields and validations

| Field | Rules |
|-------|--------|
| `due_date` | Required on create; ISO date (`YYYY-MM-DD`); sanitized |

- Invalid/missing → `400` (RNF03); no partial save of invalid date.

### Acceptance criteria

- **AC1:** Given a valid due date, when Developer saves, then it is stored and shown on the card.
- **AC2:** Given an invalid date format, when save is attempted, then `400` with a clear error and no change (RNF03).
- **AC3:** Given missing due date on create, when submitted, then `400` (RN02).
- **AC4:** Given Viewer, when they try to change due date, then `403`.

### Endpoints

- `POST /api/tasks`, `PUT /api/tasks/{taskId}` with `due_date`

### Files / modules

- Date input in forms, card due-date display, validation in task service, `tests/test_task_due_date.py`

### Definition of done

- [ ] Due date on create/edit + display
- [ ] Validation messages
- [ ] Pytest for valid/invalid/missing/403

### NFRs / role impact

- RNF03; **Developer** sets due date; **Viewer** denied

### Out of scope

- Reminders / calendar integrations / overdue automation
