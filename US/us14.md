## Original

Como Desarrollador quiero que la rama principal esté protegida para que ningún cambio se fusione ni se despliegue si las pruebas automatizadas fallan.

## Enhanced

**Story:** As a Developer, I want the main branch protected so that no change is merged or deployed if automated tests fail (RN03).

**Priority:** High | **Related:** RN03, US12, US13, US15

### Behavior

1. Repository enables branch protection on `main`.
2. Pull requests targeting `main` require a successful CI check (Pytest workflow from US12/US13) before merge.
3. Direct pushes to `main` are disabled (or restricted) according to team policy for the academic repo.
4. Failed CI blocks merge; passing CI allows merge (subject to review rules if enabled).
5. Deployment (US15) must only run after successful verification — protection + required checks prevent shipping broken main.

### Fields and validations

- N/A. Configuration: GitHub branch protection + required status checks matching the CI workflow name.

### Acceptance criteria

- **AC1:** Given a PR to `main` with failing CI, when merge is attempted, then GitHub blocks the merge.
- **AC2:** Given a PR to `main` with passing CI, when protection rules are satisfied, then merge is allowed.
- **AC3:** Given RN03, when documented/configured, then merge to `main` and deploy depend on passing automated tests.
- **AC4:** Given branch protection settings, when reviewed by the team, then `main` requires the Pytest CI check.

- N/A (GitHub repository settings / Rulesets). Optionally documented as a checklist in `docs/development_guide.md`.

### Files / modules

- Repo settings (GitHub UI or rules-as-code if used)

### Definition of done

- [ ] `main` protected
- [ ] Required CI check configured
- [ ] Team verified failing PR cannot merge
- [ ] RN03 reflected in docs

### NFRs / role impact

- Process reliability; all Developers; Admin of the GitHub repo configures protection

### Out of scope

- Writing the tests themselves (US13), CD publish steps (US15)
