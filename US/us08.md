## Original

Como Desarrollador quiero asignar un único responsable registrado a cada tarea para clarificar quién debe completarla.

## Enhanced

**Story:** As a Developer, I want to assign a single registered user as the responsible for each task so that ownership is clear.

**Priority:** High | **Related:** RF04, RN01, US03 (users exist), US05/US06

### Behavior

1. On create or edit, Developer picks an assignee from registered users.
2. Backend stores at most one `assignee_id` (RN01).
3. Replacing assignee updates to the new user only (no multi-assignee).
4. Card shows the assignee name/label.
5. Assignee must reference an existing User; invalid id → `400`.

### Fields and validations

| Field | Rules |
|-------|--------|
| `assignee_id` | Optional or required by product default: if set, must exist; only one primary assignee (RN01) |

### Acceptance criteria

- **AC1:** Given Developer selects a registered user, when saved, then the task has that single assignee and the card shows it.
- **AC2:** Given a task already has an assignee, when Developer assigns another user, then only the new assignee remains (RN01).
- **AC3:** Given an invalid `assignee_id`, when saved, then `400` and no invalid FK is stored.
- **AC4:** Given Viewer, when they try to change assignee, then `403`.

### Endpoints

- `POST /api/tasks` / `PUT /api/tasks/{taskId}` with `assignee_id`
- `GET /api/users` (reduced list for assignee picker as allowed)

### Files / modules

- Assignee select in create/edit forms, task service RN01 checks, `tests/test_task_assignee.py`
