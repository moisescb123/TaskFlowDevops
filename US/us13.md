## Original

Como Desarrollador quiero que existan pruebas automatizadas en el flujo de integración continua para detectar defectos antes de fusionar los cambios.

## Enhanced

**Story:** As a Developer, I want automated tests in the CI pipeline so that defects are detected before changes are merged.

**Priority:** High | **Related:** US12, RN01–RN04 coverage goals, Pytest, TDD in `docs/base-standards.md`

### Behavior

1. Project includes a Pytest suite covering core domain behavior (authz, RN01–RN04, task CRUD as implemented).
2. CI workflow (US12) executes `pytest` (or `python -m pytest`) after installing dependencies.
3. Failing tests mark the CI run as failed so Developers see breakages before merge.
4. Tests use an isolated SQLite DB (in-memory or temp) and do not depend on developer machine state.

### Fields and validations

- N/A. Tests assert API/domain validations (e.g., RN02 required fields, RN04 illegal transitions).

### Acceptance criteria

- **AC1:** Given the repo has tests, when CI runs, then Pytest executes in the workflow.
- **AC2:** Given a failing test, when CI completes, then the check fails.
- **AC3:** Given all tests pass, when CI completes, then the check succeeds.
- **AC4:** Given business rules RN01–RN04 are implemented, when the suite runs, then there is automated coverage for each rule (as features land).
- **AC5:** Given Developer runs Pytest locally, when using the same commands as CI, then results are consistent.

### Endpoints

- Tests exercise app endpoints from `docs/api-spec.yml` (auth, users, tasks) as those features exist.

### Files / modules

- `tests/` (e.g. `test_auth_*.py`, `test_task_*.py`)
- `pytest.ini` or `pyproject.toml` test config
- CI step invoking Pytest in `.github/workflows/ci.yml`

### Definition of done

- [ ] Pytest suite in repo
- [ ] CI runs Pytest on push/PR
- [ ] Critical rules covered as features are implemented
- [ ] Local run instructions documented

### NFRs / role impact

- Quality/reliability of delivery; Developers rely on red/green checks; no end-user role UI

### Out of scope

- Branch protection enforcement (US14), deployment (US15), E2E browser suite (optional later)
